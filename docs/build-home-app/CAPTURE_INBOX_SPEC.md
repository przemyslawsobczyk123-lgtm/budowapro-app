# Capture inbox - Task 6.3

## Objective

Provide one project-scoped, offline inbox for quick capture. A capture is not a
cost, schedule event, checklist result or report record until the user reviews
and explicitly classifies it.

## Supported capture types

- photo,
- document,
- note,
- voice file,
- cost,
- task,
- decision,
- defect.

Receipt capture continues to use the reviewed OCR flow from Tasks 6.1-6.2.

## Data and states

Each capture stores a stable ID, project ID, proposed type, title, optional text,
zero or more private attachment links, processing status, missing-context
reasons, optional target reference and UTC timestamps.

Open states:

- `needs_review`: required context is missing,
- `ready`: enough context exists for explicit approval.

Terminal state:

- `classified`: the user approved the capture and it is no longer in the open
  inbox.

Missing context is deterministic from the capture type and fields. It is never
generated by AI.

## Classification

- Photo, document and voice captures create document metadata for every linked
  private attachment.
- Cost captures create an existing financial `draft`; they remain outside all
  budget summaries until the normal cost approval flow confirms them.
- Task captures create an existing local schedule task.
- Note, decision and defect captures become classified inbox records. Their
  dedicated target modules are Tasks 7.1, 7.2 and 9.3; Task 6.3 does not create
  placeholder domain tables that would conflict with those modules.

Document, cost and task classification updates the capture and target in one
SQLite transaction.

## Merge and rejection

Two open captures from the same project can be merged. Text and attachment links
move to the retained capture in one transaction. A rejected capture is removed.
After the row and links are removed, every attachment is deleted only when no
other record uses it. Interrupted file deletion is handled by the existing local
attachment recovery.

## UI

- A global `+` action opens quick capture for the selected project.
- Start and More show the open inbox count and open the same inbox.
- The inbox supports open/history views and compact type filters.
- Every row shows type, date, missing-context reason and available actions.
- Empty, loading and error states must work at a 320 px viewport and 200% text
  scaling.

## Boundaries

- No account, backend, upload, telemetry or microphone permission.
- Voice is imported through the Android system audio picker in Task 6.3.
- Attachment contents, paths, titles and notes are never logged.
- Capture rows never contribute to budget, progress or reports.
